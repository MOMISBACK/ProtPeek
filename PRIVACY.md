# ProtPeek privacy policy

Last updated: 19 October 2026

ProtPeek does not operate a backend and does not include analytics, advertising, telemetry, user accounts, or profiling.

## Zotero desktop plugin

The Zotero prototype reads the selected paper's local attachment and limited reference metadata to detect identifiers on the computer. It does not upload document text, annotations, library records, or local structure files, and does not modify references or annotations.

The Zotero viewer saves its white or black background choice in a namespaced local Zotero preference. This contains no article text or structure history. No preference or filesystem API is exposed to the viewer beyond reading and saving this display choice.

Remote structures are fetched only after an explicit Open action, using the same providers described below. Zotero may independently contact `raw.githubusercontent.com` to check the plugin's update metadata. This prototype's update feed is empty and updates are manual. Update checks do not include paper content or library records. Zotero's own synchronization and other networking remain separate from ProtPeek.

## What ProtPeek processes

### Article scanning

While the ProtPeek panel is open, the extension can inspect the active web page to detect PDB, UniProt, and AlphaFold identifiers. Detection is performed locally in the browser. Page text and article content are not uploaded to ProtPeek, RCSB, AlphaFold, or another service.

Only the detected identifiers and small amounts of session metadata needed to coordinate the side panel are passed between extension components.

### Local structure files

Local `.pdb`, `.cif`, `.mmcif`, and `.bcif` files are read and rendered locally. ProtPeek does not upload or create a cloud copy of them.

Exporting a structure or PNG is also performed locally before the browser saves the generated file.

### Remote structures

When you explicitly open a remote identifier, ProtPeek contacts the official structure provider needed for that request:

| Request | Service |
| --- | --- |
| PDB structure | `models.rcsb.org` or `files.rcsb.org` |
| UniProt / AlphaFold model | `alphafold.ebi.ac.uk` |

ProtPeek sends the requested identifier as part of the provider request. As with ordinary web traffic, the provider may receive technical information such as your IP address, request time, user agent, and transport headers. Those services apply their own privacy policies.

## Storage

ProtPeek uses browser session storage to coordinate the active page and side panel. It may temporarily contain detected identifiers, the source tab ID, a pending identifier selected from the context menu, and an optional scan error.

This storage is session-scoped and is not used as a persistent history. The white or black viewer background preference is saved in browser local storage on this device. It contains no article text or structure history and is not synced or transmitted. Structure data and other viewer state remain in memory while needed.

To schedule an optional review invitation, the browser extension also stores the date of first successful use, the most recent active day, a counter capped at five active days, the number of invitations shown, a reminder date, and the dismissal preference locally on this device. These values are not synced or transmitted and contain no file names, structure identifiers, page URLs, or article content. The invitation appears only after at least seven days and five active days, at most twice with a 30-day interval. Choosing “Don’t ask again” or opening the store review page stops further invitations. Opening the review page is an explicit user action and is subject to the store’s own privacy policy.

ProtPeek does not store browsing history, cookies, account credentials, analytics identifiers, or advertising identifiers.

## Browser permissions

ProtPeek requests only the permissions needed for its browser integration:

- access to HTTP/HTTPS pages so it can scan the active article locally;
- `scripting` to run the article scanner;
- `contextMenus` for **View in ProtPeek** on a selected identifier;
- `storage` for session-scoped communication between extension components and the local viewer background and review-invitation preferences;
- Chromium `sidePanel` support generated by WXT.

The extension's content security policy restricts its structure-data connections to the official RCSB PDB and AlphaFold hosts.

Firefox describes user-entered or selected structure identifiers under its `searchTerms` data category because those identifiers can be sent to the selected structure provider. ProtPeek does not use them for analytics or profiling.

## Data sharing and sale

ProtPeek does not sell personal data and does not share data with advertisers or analytics providers. Remote structure identifiers are disclosed only to the structure provider required to fulfil the user's request.

The source code is public at <https://github.com/MOMISBACK/ProtPeek>.
